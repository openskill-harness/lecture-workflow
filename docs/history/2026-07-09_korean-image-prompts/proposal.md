# 제안: 이미지 프롬프트를 한글로 (사용자 개입 지점의 언어 일치)

- 날짜: 2026-07-09
- 선행: `docs/history/2026-07-09_user-intervention-tools/` (사용자 확정 우선 원칙, origin 필드)

## 1. 배경 / 문제

사용자가 원고와 PPT프리뷰를 눈으로 보고 확정한다(개입 지점). 그런데 원고의 `GPT image prompt:`는 스키마가 **영문**을 강제한다:

> `manuscript-schema.md` §4: "백틱으로 감싼 영문 프롬프트 한 줄"

사용자가 "이 그림 말고 이렇게" 라고 개입하려면 그 프롬프트를 읽고 고쳐야 한다. 개입 지점의 언어가 영문이면 개입 비용이 올라간다. 이는 방금 도입한 `origin: user-prompt`(사용자가 준 프롬프트를 하네스가 임의로 다듬지 않는다)와도 맞지 않는다 — 사용자가 쓰는 언어로 프롬프트를 남길 수 있어야 한다.

기술적 장애물은 없다. `image_gen.py:105`가 프롬프트를 `'다음 설명으로 이미지 한 장을 생성해서 PNG 파일로 저장해줘:\n' + prompt`로 이미 **한국어 지시문**에 실어 Codex에 넘긴다. 프롬프트 본문만 영문일 이유가 없다.

## 2. 함께 드러난 두 가지 정합성 문제

### (a) 골든과의 충돌

`manuscript-schema.md` 3행이 precedence를 이렇게 정한다:

> **기준(golden)은 `templates/golden/manuscript_golden.md`** … 이 문서와 골든이 어긋나면 골든이 맞다.

골든에는 영문 프롬프트가 10개 있다. 스키마만 한글로 바꾸면 "골든이 맞다"는 조항 때문에 규범이 자기모순에 빠진다.

### (b) dead-reference 예정

같은 3행이 `(= courses/spring-boot-basic/manuscripts/ch01.md와 동일 내용)`이라 적는다. 사용자가 `spring-boot-basic` 과정을 삭제하기로 했으므로 이 경로는 곧 dead-link가 된다(R1: 옛 경로/dead-link는 인라인에 남기지 않는다).

## 3. 제안

### A. 프롬프트 언어를 한글로 (`manuscript-schema.md` §4)

- `GPT image prompt:` / `User image prompt:` / `Comic panel prompt:` 의 프롬프트 본문을 **한글 한 줄**로 쓴다.
- 이미지에 글자를 넣지 않는다는 지시("글자 없이")는 계속 명시한다 — 생성 이미지의 한글 글리프가 깨지기 때문이며, 이는 언어 변경과 무관한 기존 제약이다.
- 근거를 현재형으로 남긴다: 사용자가 읽고 고치는 지점이므로 사용자의 언어로 쓴다.

### B. 골든의 프롬프트 10개를 한글로 교체 (`templates/golden/manuscript_golden.md`)

규범 파일이 새 규칙의 반례가 되면 안 된다. 프롬프트 **본문만** 한글로 바꾸고 라벨·구조·문체·다른 필드는 손대지 않는다. 이미지 내용(구도·요소)은 원문과 동일하게 옮긴다.

### C. `manuscript-schema.md` 3행 정정

- `(= courses/spring-boot-basic/manuscripts/ch01.md와 동일 내용)` 삭제 (dead-reference 예정).
- precedence를 범위 지정으로 교체: 골든은 **필드 표기·순서·문체**의 기준이다. 제안 B로 골든도 한글이 되므로 프롬프트 언어에서 스키마와 골든이 어긋나지 않는다.

## 4. 범위 밖 (건드리지 않는다)

- **확정 원고의 기존 영문 프롬프트** — `courses/design-pattern/outputs/02_원고/ch01.md`(11개). 확정 산출물이고, 프롬프트를 바꾸면 해시가 달라져 `visual-assets`가 그 슬라이드를 `stale`로 잡아 이미 승인된 이미지 11장을 전부 재생성한다. 규칙은 새로 쓰는 원고부터 적용한다.
- `image_gen.py` / `build_asset_manifest.py` — 언어 비의존. 변경 없음.
- `IMG_PROMPT_RE` — 라벨만 매치하고 본문 언어를 보지 않는다. 변경 없음.

## 5. 회귀 위험

| 위험 | 완화 |
|---|---|
| 한글 프롬프트로 Codex 이미지 품질 저하 | `image_gen.py`가 이미 한국어 지시문으로 감싸 호출한다. 첫 차시(ch02) 생성 결과를 사용자가 육안 확인 후 판단 |
| 생성 이미지에 깨진 한글 글자가 렌더됨 | "글자 없이" 지시를 프롬프트 규칙에 유지(기존과 동일) |
| 골든 편집이 문체 규범을 훼손 | 프롬프트 본문 라인만 교체. 필드 라벨·순서·Narration·구조 무변경 |
| ch01(영문)과 ch02(한글)가 한 과정에 공존 | 원고는 과정별 산출물이지 권위 문서가 아니다(R2 적용 대상 아님). 재생성 폭포를 막는 것이 우선 |
| 스키마 3행 precedence 완화가 표기 드리프트를 부름 | 골든 우선은 **필드 표기·순서·문체**로 범위를 명시해 유지 |

## 6. 검증

- 골든 프롬프트 10개가 전부 한글이고 라벨/필드 수는 불변인지 grep.
- `IMG_PROMPT_RE`가 한글 프롬프트를 여전히 추출하는지 단위 확인.
- drift grep 4종 0 (특히 dead-link: `spring-boot-basic` 참조 잔재).
