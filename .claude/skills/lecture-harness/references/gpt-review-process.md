# GPT 교차 검증 절차

설계 시점에 결정되는 **구조적 사항**은 GPT를 CLI로 spawn하여 교차 검토·검증을 거친다. 이 규칙은 CLAUDE.md에도 등록되어 있다.

## 원칙: 사전 검증 — 선반영 금지 (v1.6.1, 사용자 지시)

사용자의 질문형 요청·제안·품질 피드백은 실행 지시가 아니다. 구조 변경의 순서는 항상:

```text
① 변경 계획서 작성 (docs/proposals/{날짜}_{주제}.md)
   — 배경(피드백 원문) / 제안 변경(항목별) / 대안 / 영향 범위(수정될 파일) / 되돌리기 방법
② codex 사전 검증 — 계획서를 검토시킨다. 정합성만이 아니라 "이 아이디어가 좋은 방법인가"
   (항목별 장점 / 리스크 / 더 나은 대안 / 반대 의견). 사용자 아이디어라도 반대 근거가 있으면 그대로 보고
③ 사용자 보고 — 항목별 [계획 + codex 의견 + 내 의견 + 권고]
④ 승인된 항목만 반영
⑤ 반영 후 정합성 검증 (아래 기존 절차)
```

파일을 먼저 고치고 나서 검증을 돌리는 것(선반영)은 금지다. 이유: 검증의 목적은 잘못된 결정이 반영되기 전에 막는 것이며, 반영 후 검증은 매몰비용 때문에 되돌림 판단을 왜곡한다.

## 대상 (구조적 결정만)

| 시점 | 검토 대상 |
|------|----------|
| **사용자 제안/피드백으로 구조 변경을 계획할 때 (사전, 필수)** | 변경 계획서 — 아이디어 타당성 포함 |
| 설계 문서 작성/개정 직후, 사용자 승인 요청 전 | 설계 문서 전체 |
| 공통 스키마(Manifest/Lesson Plan/Registry 등) 변경 | 변경 스키마 + 영향받는 오케스트레이터 |
| 라인 파이프라인/품질 게이트 변경 | 해당 라인 스킬 |
| 에이전트/스킬 추가·수정 | 신규 정의 + 기존 구성과의 중복 여부 |

일상적 산출물 생성(원고, 슬라이드, 코드 등)은 대상이 **아니다**.

## 실행 방법

도구: OpenAI Codex CLI (`codex`). 반드시 비대화형으로, **stdin을 닫고** 실행한다.

```bash
# Git Bash (권장) — stdin을 닫지 않으면 "Reading additional input from stdin..."에서 hang된다
codex exec --sandbox read-only '<검토 프롬프트>' </dev/null
```

주의사항 (운영 중 확인된 것):
- PowerShell 백그라운드 실행 시 stdin 대기로 멈춘다. Git Bash + `</dev/null`을 사용한다.
- `--sandbox read-only`로 실행한다 (검토자는 파일을 수정하면 안 된다).
- 출력이 크면 마지막 부분(최종 보고)만 취한다.
- 검토 대상 파일 경로를 프롬프트에 명시해 codex가 직접 읽게 한다.

## 검토 프롬프트 계약

프롬프트에 다음을 요구한다:

1. 결정사항이 상위 문서(`docs/claude-handoff-lecture-harness.md`, `docs/harness-design-v1.md`)의 확정 사항과 충돌하는지
2. 누락된 산출물/게이트/에러 경로가 있는지
3. 과잉 설계(불필요한 에이전트/스킬/단계)가 있는지
4. 각 지적에 심각도(blocker / warning / suggestion) 부여
5. 지적 없으면 "지적 없음" 명시

## 결과 처리

- 결과를 `docs/reviews/{YYYY-MM-DD}_{대상}.md`로 저장한다: 지적 요약 + 처리 내역(반영/비반영+사유) + 원문 핵심.
- **blocker**: 사용자 보고 전에 수정하거나, 수정하지 않으면 사유를 병기한다.
- **warning/suggestion**: 채택 여부를 사용자 보고에 병기한다. 최종 결정은 사용자.
- GPT 의견이 인수인계 문서/사용자 확정 사항과 충돌하면 **사용자 확정이 우선**한다.
- codex CLI 실패/미설치 시 검증을 건너뛰되 보고에 "GPT 교차 검증 생략됨"을 명시한다.
- 반영으로 문서/스킬이 바뀌면 `docs/harness-changelog.md`에 기록한다 (설계 규범 변경이면 설계 문서 개정 이력에도).
