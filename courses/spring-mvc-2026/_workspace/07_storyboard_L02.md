# L02 슬라이드 스토리보드 — HTTP 요청 한 건이 MVC 내부를 통과하는 흐름 추적

## 설계 개요

- **물리 5장 + 편집 마커 1(CUE-B) = 마커 총 6(콘텐츠 3 + cue 3), 물리 렌더 5.** 레슨의 **본체는 별도 시뮬레이터**(`시뮬레이터_MVC요청흐름.html`)이며, 슬라이드는 **도입 → 시뮬레이터 진입 → (시뮬레이터가 본론) → 정리 → L03 다리**의 프레임만 담당한다. **STEP 0~12(모드 A/B)의 관문 내용은 시뮬레이터가 화면으로 말하므로 슬라이드에 복제하지 않는다.**
- **마커 대응(1:1).** 프롬퍼의 콘텐츠 마커 `[SLIDE 01]·[SLIDE 02]·[SLIDE 03]` → 콘텐츠 슬라이드 3장. 프롬퍼의 조작 마커 `[SIM 실행]·[SIM 리셋→모드②]·[SIM 종료]` → cue 슬라이드 3장. `[SIM STEP n]` 마커(모드 A 11개 + 모드 B 6개)는 **시뮬레이터 내부 나레이션 큐**이므로 슬라이드를 만들지 않는다.
- **1장 = 1메시지 준수.** 콘텐츠 3장 모두 단일 메시지. SLIDE 02(정리)는 "반환값이 출구를 가른다"라는 **하나의 대조 메시지**이고, 두 갈래는 그 대조의 양변이므로 분할하지 않는다(프롬퍼의 단일 `[SLIDE 02]` 블록과 동일).
- **cue 슬라이드 내용 규칙.** cue 슬라이드에는 **[실행 파일명 / 조작 요약 / 화면 전환 지시]만** 담는다. 관문 설명·다이어그램 금지(그 역할은 시뮬레이터). 화면 소스(슬라이드↔시뮬레이터) 전환의 편집 기준선 역할.
- **단어 수 카운트:** 본문(제목+라벨+칩) 어절 기준. cue 슬라이드의 조작 지시문도 본문에 포함해 카운트. 하단 각주(출처)는 본문 단어 수에서 제외하되 1행 유지.
- **비주얼 연속성:** 시뮬레이터의 "관문 열(row)" 이미지를 SLIDE 03에서 **축소 재사용**하여 "우리가 앞뒤 관문만 봤고 STEP 7 Controller 안은 안 열었다"를 시각적으로 잇는다(원고 마무리와 일치). SLIDE 02의 분기 노드도 시뮬레이터 색계(모드 A=인디고/시안, 모드 B=그린/앰버)를 따른다.

### duration 주석 (오케스트레이터 보고 대상 — 임의 수정 안 함)

- 본 스토리보드는 지시대로 **L02 = 편1 소속, 10분 재배분**을 기준으로 설계했다.
- 단, `scripts/L02.md`·`scripts/L02_prompter.md`의 헤더는 아직 **`duration: 7분`**으로 표기되어 있고, `_workspace/06_prompter_L02_length.md`도 7분 대역 기준으로 **FAIL(+39%)** 판정된 상태다. 프롬퍼 실측 2,913자는 **10분 대역(250~300자/분 → 2,500~3,000자)에는 정합**하므로 재배분이 길이 문제를 해소한다.
- **이는 원고 내용 불일치가 아니라 헤더/판정 문서의 duration 표기 드리프트**다. 스토리보드에서 원고를 바꾸지 않았고, 헤더 정정은 오케스트레이터에 보고한다(재호출 지침·에러 핸들링 준수).

  - 제목: `요청 한 건을, 순서대로 따라간다`
  - L01 콜백 칩(작게, 좌상단): `L01 안내데스크 →` (원고 "L01의 안내데스크, 기억나시죠" / boundary_in)

  - 핵심 프레임(강조, 하단): `딱 하나만 — 저 관문이, 왜 거기 있는가` (accent 컬러; 원고의 관찰 프레임)
  - 강조: 프레임 문장을 accent로. 재료 칩은 차분하게(질문을 남기고 시뮬레이터로 진입).

## SLIDE 02 — 정리 진입: 반환값이 출구를 가른다 (콘텐츠)

- **프롬퍼 대응:** `[SLIDE 02]` (원고 §3 정리 앞부분)
- **화면 소스:** 슬라이드
- **핵심 메시지(한 줄):** 두 경로는 STEP 6(preHandle)까지 한 몸이고, 갈린 지점은 **컨트롤러가 무엇을 반환하느냐** 하나다 — 객체를 반환하면 직렬화·커밋(뷰 없음), 뷰 이름을 반환하면 ViewResolver로 View를 만들어 렌더링. 같은 데스크, 반환값에 따라 다른 출구.
- **구성 요소 명세:**
  - 제목: `반환값이 출구를 가른다`
  - 공통 구간 바(좌): `STEP 0 → 6 preHandle` 라벨 `여기까진 한 몸` (원고 "preHandle까지는 한 몸")
  - 분기 노드(중앙, accent): `무엇을 반환?`
  - 갈래 A(상, 모드 A 색계): `객체 (@ResponseBody)` → `HttpMessageConverter 직렬화·커밋` · 배지 `뷰 없음`
  - 갈래 B(하, 모드 B 색계): `뷰 이름` → `ViewResolver → View 렌더링`
  - 하단 라벨: `같은 데스크 · 다른 출구`
  - **범위-밖 방백 처리:** HandlerExceptionResolver "안전망"은 원고가 **"오늘 흐름 바깥"**으로 자기표기 → **작은 회색 각주 라벨 1행**으로만: `예외 → HandlerExceptionResolver (오늘 흐름 밖)`. 다이어그램 본류에 넣지 않음. (프롬퍼 길이 조정 시 06_length Tier-1 A로 생략 가능 — 스토리보드는 원고 충실 유지하되 시각 비중 최소.)
  - 강조: 분기 노드 accent. A는 "커밋"(잠금 느낌), B는 "렌더링"(추가 공정) 대비. 시뮬레이터가 이미 실연했으므로 **재설명이 아니라 한 화면 대조 요약**으로 조립(스텝별 재서술 금지).
- **단어 수 추정:** 약 22어절 (제목 3 + 공통바 3 + 분기 2 + A갈래 6 + B갈래 4 + 하단 4; 각주 라벨 제외). **PASS (≤45)** — 콘텐츠 최다 밀도 슬라이드지만 여유 있음.
- **각주:** `Spring Framework Reference — Interception(직렬화·커밋 타이밍) / Special Bean Types(ViewResolver)` — citation_required(version_specific_claims). (시뮬레이터 STEP 8·10에서 인용한 것과 동일 출처의 요약 표기.)

## SLIDE 03 — 마무리: L03로 넘어가는 다리 (마무리 고정, 콘텐츠)

- **프롬퍼 대응:** `[SLIDE 03]` (원고 §3 정리 뒷부분, boundary_out)

- **구성 요소 명세:**
  - 제목: `우리가 안 열어본 한 곳`
  - 다이어그램: **시뮬레이터 관문 열(row)의 축소 재사용** — 앞뒤 관문(Mapping·Adapter·preHandle·postHandle 등)은 **흐리게(dim)**, 가운데 `STEP 7 Controller` 박스만 **닫힌 상자(자물쇠/물음표)**로 강조. (원고 "앞뒤 관문뿐 / 안은 안 열었다"의 시각화)
  - 질문 라벨(강조, accent): `이 안엔 무엇이 들어가야 할까?` (원고 "이 Controller 안에는 대체 무엇이")
  - 다음 카드(우): `L03 — Controller 안을 연다`
  - 강조: 닫힌 STEP 7 박스에 시선 집중. 예고 톤. **SIM/실행 마커 넣지 말 것**(이 장은 예고 텍스트만, 원고에 재실행 없음).
- **단어 수 추정:** 약 14어절 (제목 4 + Controller 박스 1 + 질문 5 + 다음 카드 4). **PASS**
- **각주:** 없음 (요약·예고 슬라이드)
