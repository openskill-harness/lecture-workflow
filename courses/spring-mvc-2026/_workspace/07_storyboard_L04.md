# L04 슬라이드 스토리보드 — 기본 Controller 구현 (편2)

> 촬영 흐름: **슬라이드는 각 IDE 화면 앞의 브리지 카드**로 짧게 들어가고, 카메라가 IDE로 컷 전환된다. 실행 결과 강조 카드(S8)와 마무리 지도(S9)만 IDE 뒤에 온다. 슬라이드가 코드를 낭독하지 않는다 — diff는 IDE가 보여준다.

---

## S1 — 편2 오프닝 / 타이틀
- **핵심 메시지:** 말로 그린 책임 경계를, 오늘은 코드가 자리를 옮기는 것으로 확인한다.
- **구성 요소 명세:**
  - 상단 라벨: `편 2`
  - 제목: **기본 Controller 구현**
  - 부제: 요청 매핑부터 응답까지
  - 본문 1줄: "지난 시간 말로 그린 책임 경계를, 오늘 코드가 자리를 옮기는 것으로 확인한다"
  - 하단 비유 회수 바(L03): `웨이터 = Controller` · `주방 = Service`
  - 코드 없음. 다크 테마 타이틀 레이아웃.
- **단어 수:** ~26 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 00-starter]` **앞** (레슨 시작 오프닝)

## S2 — 오늘 만드는 건 딱 둘
- **핵심 메시지:** 오늘 새로 만드는 건 Controller·Service 둘뿐, 나머지는 준비돼 있고 지금은 404다.
- **구성 요소 명세:**
  - 제목: 오늘 만드는 건 딱 둘
  - 강조 2항목: `MemberController` · `MemberService`
  - 대비 회색 그룹(준비됨): 도메인 · 저장소 · DTO · 빌드 = 이미 준비됨
  - 하단 강조 배지: `POST /members → 404` — "받을 문이 아직 없다"
  - 코드 없음(식별자 토큰만). 신규 2 vs 기존 4 대비 배치.
- **단어 수:** ~21 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 00-starter]` **앞** (S1 직후, starter 프로젝트 보여주기 직전)

## S3 — 브리지 step-01: 요청이 도착할 문
- **핵심 메시지:** 먼저 요청이 도착할 진입점(문)부터 만든다 — 매핑은 로직이 아니라 선언이다.
- **구성 요소 명세:**
  - 캡션: `step-01 · 요청 매핑`
  - 메시지 1줄: "먼저, 요청이 도착할 문부터 만든다"
  - 핵심 변경 1줄 **코드(폰트 ≥22pt, monospace):** `@PostMapping("/members")`
  - 뜻 풀이 1줄: "이 경로·이 방식이 오면 → 이 자바 메서드 실행 (선언)"
  - change_reason(step-01) = "진입점이 필요하다"의 슬라이드화.
- **단어 수:** ~18 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 01-request-mapping]` **앞** (브리지 후 IDE로 컷)

## S4 — 브리지 step-02: 데이터 왕복
- **핵심 메시지:** 문으로 데이터를 받고 결과를 돌려준다 — 입구·출구는 도메인이 아니라 전용 DTO.
- **구성 요소 명세:**
  - 캡션: `step-02 · 요청/응답 데이터 흐름`
  - 메시지 1줄: "문으로 데이터를 받고, 결과를 돌려준다"
  - 다이어그램(도형): `SignUpRequest` → [ Controller ] → `SignUpResponse` (입구·출구 화살표)
  - 하단 1줄: "입구·출구는 도메인이 아니라 요청·응답 전용 DTO"
  - 코드 대신 식별자 라벨만. 필요 시 `@RequestBody`를 입구 화살표에 배지로(≥22pt).
- **단어 수:** ~17 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 02-request-response-dto]` **앞**

## S5 — 브리지 step-03: 뚱뚱한 컨트롤러(일부러)
- **핵심 메시지:** 중복 금지 규칙을 일단 컨트롤러 안에 넣는다 — 동작은 하지만 컨트롤러가 규칙까지 떠안는다.
- **구성 요소 명세:**
  - 캡션: `step-03 · 뚱뚱한 컨트롤러 (일부러)`
  - 메시지 1줄: "중복 금지 규칙을, 일단 컨트롤러 안에 넣는다"
  - 경고 톤 1줄(주의색): "동작은 한다 — 하지만 컨트롤러가 규칙까지 떠안았다"
  - 시각: Controller 박스가 '요청 처리 + 가입 규칙' 두 덩어리를 동시에 안고 있는 도형(과부하 강조).
  - 코드 없음(diff는 IDE). "일부러"를 색/아이콘으로 표시.
- **단어 수:** ~17 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 03-fat-controller]` **앞**

## S6 — 브리지 step-04: 책임 이동 (오늘의 핵심 장면 · 웨이터→주방 회수)
- **핵심 메시지:** 검사·저장 블록이 컨트롤러에서 서비스로 이사한다 — 홀 서버는 주문만, 주방이 요리를. 새 로직이 아니라 자리만 옮긴 것이며, 나누는 기준은 변경 이유다.
- **구성 요소 명세:**
  - 캡션: `step-04 · 책임 분리 (오늘의 핵심 장면)`
  - 메시지 1줄: "규칙 블록이 컨트롤러 → 서비스로 이사한다"
  - **비유 회수 바(L03 central_metaphor):** `홀 서버(웨이터) = 주문만` · `주방(셰프) = 요리를` — step-03의 "웨이터가 주방일까지 하던" 상태를 여기서 해소.
  - 다이어그램(핵심): '검사·저장 블록' 카드가 `MemberController` 박스에서 화살표 ⟶ `@Service MemberService` 박스로 **이동**하는 애니메이션/화살표. Controller는 홀쭉해지고 Service가 규칙을 받음.
  - 하단 1줄: "새 로직 아님 — 자리만 옮겼다. 변경 이유로 나눈다"
  - 코드는 diff(IDE) 담당. 슬라이드는 '이사' 도형 + 비유 회수에 집중. (선택: `memberService.signUp(request)` 위임 1줄을 홀쭉해진 Controller 쪽 라벨로, ≥22pt.)
- **단어 수:** ~26 (≤45 PASS)
- **대응 마커:** `[IDE 화면: 04-service-extracted]` **앞** (이 브리지가 03→04 전환의 의미를 세운 뒤 IDE에서 실제 블록 이동 diff를 보여줌)

## S7 — 브리지 step-05: 상태 코드로 결과를 말한다
- **핵심 메시지:** "응답까지"의 마지막 조각은 상태 코드 — 성공은 201, 중복은 409.
- **구성 요소 명세:**
  - 캡션: `step-05 · 응답까지`
  - 메시지 1줄: "결과를 HTTP 상태 코드로 말한다"
  - 대비 2배지: `성공 → 201 Created` · `중복 → 409 Conflict`
  - 하단 1줄: "@ExceptionHandler = 500으로 새기 전에 낚아채는 그물"
  - 코드 없음(개념 배지). 201=성공색/409=충돌색 대비.
- **단어 수:** ~19 (≤45 PASS)
- **대응 마커:** `[IDE 화면: final]` **앞**

## S8 — 실행 결과 강조 (validation log 실측만)
- **핵심 메시지:** 실제 기동 결과가 규칙을 증명한다 — 신규 201, 중복 409, 다른 이메일 201.
- **구성 요소 명세:**
  - 캡션: `실행 결과 · 실제 기동값`
  - 결과 3줄(로그 실측, 코드 아님):
    - `alice 가입 → 201 Created · {id:1, email:alice}`
    - `alice 재시도(중복) → 409 Conflict · "이미 가입된 이메일"`
    - `bob 가입 → 201 Created · id 2로 증가`
  - 하단 강조 전환 배지: `step-03의 500  →  409` (중복이 서버 에러에서 충돌로 정정됨)
  - **데이터 출처 고정:** 05_labcode_L04_validation.log(TEST1 201 id:1 / TEST2 409 / TEST3 201 id:2)만 사용. 임의 값 금지.
- **단어 수:** ~29 (≤45 PASS)
- **대응 마커:** `[IDE 화면: final — 실행 로그/터미널]` **뒤** (라이브 터미널 시연 직후, 세 결과를 깨끗한 카드로 프리즈·강조)

## S9 — 마무리 요약: 전체 지도
- **핵심 메시지:** 매핑→DTO→분리→상태코드로 완성했고, 말로 그린 경계를 코드가 눈으로 확인시켰다.
- **구성 요소 명세:**
  - 제목: 요청 매핑에서 응답까지 — 전체 지도
  - 5스텝 요약 라인: `매핑(01) → DTO(02) → 규칙 뭉침(03) → 서비스 분리(04) → 상태 코드(05)`
  - 흐름도(원고 244행 그대로): `POST /members → Controller(매핑·DTO·상태코드) → Service(가입 규칙) → Repository(저장)`
  - 마무리 1줄: "말로 그린 경계를, 코드가 눈으로 확인시켰다"
  - 코드 없음(흐름도 라벨만). 편2 클로징 레이아웃.
- **단어 수:** ~35 (≤45 PASS)
- **대응 마커:** `[IDE 화면: final — 전체 구조 한눈에]` **동반/뒤** (원고 6절 마무리)

## composer 인수인계 메모
- S6가 유일한 '리치' 슬라이드(비유 회수 + 블록 이사 다이어그램). 나머지는 미니멀 브리지 카드로 통일해 리듬 유지.
- S8은 IDE 라이브 터미널 뒤 강조 카드 — 색으로 201(성공)/409(충돌) 구분, `500→409` 전환을 시각 포인트로.
- 코드 등장 슬라이드(S3, 선택적 S4·S6 라벨)는 monospace ≥22pt 고정. 그 외는 코드체 금지.
