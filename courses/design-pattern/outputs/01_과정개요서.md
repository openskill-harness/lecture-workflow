## 1. 과정명

유지보수성 향상을 위한 디자인패턴(Java)

## 2. 대상자

1~10년차 재직 개발자.

- Java 기본 문법(클래스·인터페이스·상속)을 사용할 수 있다.
- 실무 코드의 유지보수 문제(if-else 증식, 강한 결합, 수정 파급)를 겪어봤고, 변경에 강한 설계 역량을 강화하려 한다.
- 연차 스펙트럼(1~10년)이 넓으므로: 예제는 초심자도 따라오게 쉽게(한 예제 = 한 주제), 논의는 실무자용으로(현대 Java 관용구·Spring 실례·AI 협업 병기).

## 3. 과정목표 (1개)

반복되는 코드 설계 문제를 해결하기 위한 검증된 템플릿인 디자인 패턴을 학습하여, 수정이 쉽고 확장이 용이한 코드를 작성하는 방법을 익힌다.

## 4. 세부 학습목표 (6개)

1. 싱글톤, 팩토리 패턴 등 주요 생성 패턴을 적용하여 객체 생성 로직을 최적화할 수 있다.
2. 전략 패턴과 옵저버 패턴을 활용하여 기능 변경 시 기존 코드를 수정하지 않는 설계를 할 수 있다.
3. 코드의 결합도를 낮추고 유지보수 비용을 절감하는 자바 기반 디자인 패턴을 구현할 수 있다.
4. 프록시·어댑터·데코레이터 등 구조 패턴으로 기존 코드를 고치지 않고 기능을 제어·변환·확장할 수 있다.
5. 인터페이스 계약과 목(Mock) 객체로 의존성을 분리해, 단위 테스트와 사람·AI 병렬 개발이 가능한 구조를 만들 수 있다.
6. 리플렉션과 어노테이션으로 DispatcherServlet 축소판을 만들며 디자인 패턴의 한계와 프레임워크의 동작 원리를 설명할 수 있다.

## 7. 실습 도메인 연속성

단일 도메인 하나로 관통하는 대신, 확정 소스 `code/design-pattern-end`의 ex01~ex16을 순서대로 그대로 사용한다(한 예제 = 한 주제).

- 미니 도메인 연쇄: 자동차(ex01) → 도형(ex02) → 동물원 문지기(ex03~ex06 연속) → 선생님(ex07) → 학생 숙제(ex08) → 마트(ex09) → 알림(ex10) → 계량기(ex11) → 결제(ex12) → DB 팩토리(ex13~ex14 연속) → 커피 공장(ex15) → 게시판 컨트롤러(ex16).
- 관통 서사: **"if-else로 인한 OCP 위반을 진단하고, 패턴으로 변경에 닫힌 구조로 재설계한다"** — ch02(OCP)에서 세운 기준을 매 차시의 진단 렌즈로 재사용하고, ch15(리팩토링 종합)와 ch16(패턴의 한계 → 프레임워크)으로 회수한다.
- 매 차시 공통 리듬: 나쁜 예(문제 체감) → 패턴 적용(재설계) → 실무 실례(Spring/현대 Java) → 30분~1시간 과제.

### 실습 환경·과제 위치 규약

- 실습 환경: JDK 21(LTS) + VS Code + Extension Pack for Java. 실행은 VS Code의 ▶ Run 버튼 기준으로 안내한다.
- 실습 시작 지점: 각 차시의 실습 준비 슬라이드 이전은 눈으로 보는 설명, 그 이후부터 직접 실습한다.
- 과제 위치: 각 차시 패키지의 하위 폴더 `example`에 작성한다(예: ch01 과제 → `src/ex01/example/`, 패키지 `ex01.example`).

### 실습 코드 3단계 규약

매 차시의 실습 코드는 다음 3단계 서사로 만들고, 단계별로 수업(PPT)에 노출한다.

| 단계 | 의미 | 폴더 매핑 (`outputs/04_코드/chNN/`) |
|---|---|---|
| step1 | **뼈대** — 도메인 클래스 골격(컴파일 가능한 최소 상태) | `step1/` |
| step2 | **패턴 미적용** — if-else·강한 결합 등 문제를 안은 채 동작하는 완성 코드 | `step2/` |
| final | **패턴 적용** — 재설계된 완성 코드. `code/design-pattern-end/src/exNN` 정답본과 클래스명·패키지 일치 | `final/` |

- **원고 연동**: 원고 슬라이드도 이 순서를 따른다 — 문제 체감 슬라이드의 코드 블록은 step2에서, 재설계 슬라이드의 코드 블록은 final에서 발췌한다. 이로써 PPT프리뷰·스토리보드·책이 자동으로 단계별 코드를 노출한다.
- **검증**: `practice-code`의 단계형 규격에 따라 step1/step2/final 각각 실행 검증한다(마지막만 검증하지 않는다).
- **예외**: 문제 코드가 성립하지 않는 차시(ch01 다형성 워밍업)는 단계 없이 단일 구성 가능. ch15(before/after 내장), ch16(ref01→ref03 3단계 내장)은 원본 소스의 단계 구조를 그대로 단계 매핑으로 쓴다.
