# design-pattern-start 전환 설계

## 배경

`design-pattern-v3`(현재 저장소)는 4일(32시간) 디자인 패턴 강의를 위한 **완성된 정답 소스**다.
`ex00`~`ex14`까지 각 예제가 이미 패턴이 적용된 상태로 존재하기 때문에, 학생들에게 그대로 나눠주면
"타이핑하며 배우는" 실습 수업이 성립하지 않는다.

이를 해결하기 위해, 패턴을 적용하지 않은 "before(문제)" 상태의 코드만 담은 `design-pattern-start`를
새로 만든다. 강의 중에는 이 before 코드를 학생들과 함께 라이브 타이핑으로 리팩토링하여, 패턴이
적용된 after(해결) 상태까지 발전시킨다.

## 목표

- 각 예제(`exNN`)에 대해, 패턴 미적용 상태의 **실제로 컴파일·실행되는** before 코드를 제공한다.
- before 코드는 그 자체로 문제(중복, 강한 결합, 확장 시 수정 필요, 타입 불일치 등)를 눈으로
  확인할 수 있어야 한다.
- 강사가 수업 중 학생들과 함께 before → after로 리팩토링하는 과정을 라이브 타이핑으로 진행한다.
- 기존 `design-pattern-v3`는 손대지 않고, 강사용 정답(after) 참고본으로 유지한다.

## 비목표

- 빈칸/TODO 스텁 채우기 방식은 사용하지 않는다 (메서드 시그니처만 주고 본문을 비워두는 방식 제외).
- `design-pattern-start`에 after(해결) 코드를 미리 작성해 넣지 않는다 — after는 라이브 수업에서만 만들어진다.
- 이번 전환 작업에서 `ex15`(`ref01`/`ref02`/`ref03`, 리플렉션 기반 라우팅 한계→해결 부록 예제)는
  다루지 않는다. README 강의 목차(`ex00`~`ex14`)에 포함되지 않는 부록 자료이기 때문이다. 필요해지면
  이후 별도로 다룬다.

## 저장소 구조

```
design-pattern-start/       (design-pattern-v3와 형제 폴더, 완전히 독립된 새 git 저장소)
  src/
    ex00/ ...
    ex01/ ...
    ...
    ex14/ ...
  bin/                 (컴파일 산출물. 기존 v3와 동일하게 .class 파일도 git에 커밋)
  README.md            (학생용 실행 안내 — 기존 v3 README의 "실행 방법" 섹션을 재사용/축약)
```

- **완전히 독립된 새 git 저장소**로 만든다 — `design-pattern-v3`와 커밋 히스토리를 공유하지 않는다
  (`git worktree`로 만들 경우 정답 코드 히스토리가 그대로 딸려가 학생에게 노출될 위험이 있어 제외).
- 위치: `design-pattern-v3`의 형제 폴더 `../design-pattern-start` (즉 `부산은행/design-pattern-start`).
- 원격 저장소: `https://github.com/busan-bank-2026/design-pattern-start.git` (기존 `design-pattern-v3`의
  원격은 `https://github.com/busan-bank-2026/design-pattern-end.git` — 이름에서 알 수 있듯 "end(정답)"와
  "start(시작)" 쌍으로 운영).
- `design-pattern-v3`(및 그 `.git`)는 이번 작업에서 전혀 수정하지 않는다.
- 패키지 구조(`exNN` 네이밍, `App.java` 진입점 등)는 `design-pattern-v3`와 동일하게 미러링한다.
- 빌드/실행 방식은 기존과 동일 (JDK만으로 `javac`/`java`, 외부 라이브러리 불필요, VS Code + Java 확장 지원).

## 예제별 처리 방침

### 기존 before/after 쌍을 재활용 (신규 작성 불필요)

| 예제 | 처리 |
|---|---|
| `ex08` (옵저버) | 기존 `polling` 코드만 시작점으로 복사. `push`(옵저버 적용)는 라이브로 완성. |
| `ex13` (팩토리 메서드) | 기존 `ex12`(Simple Factory, if-else) 코드를 복사해 `ex13`의 시작점으로. Factory Method 리팩토링은 라이브로 완성. |
| `ex14` (리팩토링) | 기존 `before` 폴더만 사용. `after`는 라이브로 완성. |

### 신규 before 코드 작성 필요 (강의별 대화로 결정)

`ex00, ex01, ex02, ex03, ex04, ex05, ex06, ex07, ex09, ex10, ex11` — 현재 after(패턴 적용)만
존재하므로, 각 예제마다 "패턴이 없으면 어떤 문제가 생기는가"를 보여주는 before 코드를 새로 작성해야
한다. 이 스펙에서는 일괄적으로 정하지 않고, **1강(`ex00`)부터 순서대로 사용자와 대화하며 하나씩
확정**한다 (아래 "이후 진행 방식" 참고).

`ex01`처럼 기존 after 코드의 주석에 이미 "나쁜 예"가 의사코드로 남아있는 경우, 이를 실제로 동작하는
before 코드로 구체화하는 것이 출발점이 된다.

## 주석/안내 컨벤션

- 별도의 안내 문서(`README.md` per exercise)는 만들지 않는다. 설명은 코드 상단 주석으로만 남긴다.
- **before 코드의 주석에는 패턴 이름이나 해결 방향을 적지 않는다.** 증상/문제 상황만 서술한다.
  - 예: 기존 `design-pattern-v3`의 `ex01` 주석은 "목표: SOLID 중 OCP"와 해결 방향까지 명시하지만,
    `design-pattern-start`의 `ex01`에는 이런 스포일러 없이 "도형 종류가 늘어날 때마다 이 계산 로직을
    고쳐야 한다" 같은 증상만 남긴다.
  - 목적: 학생들이 라이브 수업에서 강사와 함께 해당 패턴을 "발견"하는 경험을 하도록 하기 위함.

## 이후 진행 방식

이 스펙은 `design-pattern-start`의 전체 구조와 원칙만 정의한다. 각 예제의 구체적인 before 코드
내용은 구현 단계에서 **`ex00`부터 순서대로, 한 강(예제) 씩 사용자와 대화하며** 확정한다:

1. 사용자가 해당 강의에서 보여주고 싶은 구체적 문제 상황을 설명한다.
2. 코드를 작성/제안하고, 컴파일·실행이 되는지 확인한다.
3. 사용자 승인 후 다음 예제로 넘어간다.

기존 before/after 쌍 재활용 대상(`ex08`, `ex13`, `ex14`)은 별도 논의 없이 파일 복사로 바로
처리한다.
