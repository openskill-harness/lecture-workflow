# course-outline 스킬

11단계 파이프라인의 1단계. 새 과정의 `courses/{id}/1.과정개요서.md`를 사용자와 **대화로** 만든다. 이 스킬은 코드가 아니라 대화 절차 문서다 — 아래 순서를 그대로 따라 진행하되, 사용자가 이미 답한 내용은 다시 묻지 않는다.

개요서의 차시표(번호·차시명·차시내용·실습 여부)는 다음 단계 `manuscript-draft`가 차시별 원고를 쓸 때 그대로 입력값이 된다(`templates/golden/manuscript_golden.md` 스키마의 "차시 정보" 헤더로 이어짐). 따라서 차시내용은 다음 사람이 원고를 바로 쓸 수 있을 만큼 구체적으로 적는다.

## 산출물
- `courses/{id}/1.과정개요서.md` — 이 단계의 확정 산출물
- `courses/{id}/research/{주제}.md` — 리서치 서브에이전트가 만드는 주장-출처 쌍 자료
- `courses/{id}/status.md` — 확정 시 `templates/status_template.md`로 신규 생성(이미 있으면 과정개요서 행만 갱신)

## 개요서 필수 섹션 (7종)
1. 과정명
2. 대상자
3. 과정목표 (1개)
4. 세부 학습목표 (N개)
5. 차시표 — 컬럼: 번호 / 차시명 / 차시내용 / 실습 여부
6. NCS 연계 (해당 시. 해당 없으면 "해당 없음"이라고 명시적으로 적는다 — 섹션 자체를 생략하지 않는다)
7. 실습 도메인 연속성 (예: 전 차시에 걸쳐 하나의 Todo 도메인으로 실습을 이어가는 방식)

## 대화 절차 (8단계)

### 1. 주제 확인
"어떤 과정을 만들까요?"라고 묻는다. 사용자가 이미 이번 대화에서 주제를 말했다면(예: "스프링 부트 심화 과정 만들자") 이 단계는 생략하고 바로 2단계로 간다.

### 2. 과정 폴더 결정 + 리서치 서브에이전트 디스패치
- 주제를 kebab-case id로 변환해 `courses/{id}/`를 정한다(예: "스프링 부트 심화" → `spring-boot-advanced`). 이미 같은 주제의 폴더가 있으면 그 id를 재사용할지 사용자에게 확인한다.
- Agent 도구(`subagent_type: general-purpose`)로 리서치를 **위임**한다. 메인 대화 컨텍스트에는 리서치 결과를 직접 채우지 않는다 — 서브에이전트가 파일을 쓰고, 메인은 그 파일을 나중에 읽어 요약만 가져온다.
- 디스패치 프롬프트에 반드시 포함할 것:
  - 조사 대상: 주제의 최신 동향, 버전/생태계 현황, 공식 문서 링크, 실무 채용 공고에서 요구하는 스킬, 유사 강의/부트캠프 커리큘럼 구성
  - 출력 형식: `courses/{id}/research/{주제}.md`에 "주장 — 출처(URL)" 쌍으로 정리해서 저장할 것(모든 주장에 출처가 붙어야 함)
  - 저장 후 서브에이전트는 파일 경로와 3~5줄 요약만 반환할 것(메인 컨텍스트 오염 방지)
- 서브에이전트가 끝나면 결과 파일 경로만 확인하고, 파일 자체는 다음 단계에서 읽는다.

### 3. 리서치 결과 설명
`courses/{id}/research/{주제}.md`를 읽고, 아직 대상자를 정하지 않은 사용자도 이해할 수 있는 눈높이로 주제를 요약해 설명한다(전문 용어를 처음부터 남발하지 않는다). 이 설명은 다음 단계(대상자 선정)의 판단 재료가 된다.

### 4. 대상자 선정 (목표보다 먼저)
**과정목표를 묻기 전에 반드시 대상자부터 정한다.** 대상자가 이후 모든 후보 제시(목표 난이도, 세부목표 수준, 예제 난이도)의 기준이 되기 때문이다.
- 후보 3개를 제시한다(예: 완전 초보 / 관련 전공 신입 / 실무 1년차). `AskUserQuestion` 도구가 있으면 활용해 선택지를 제시한다. 없으면 번호를 매겨 텍스트로 제시하고 사용자 응답을 받는다.
- 사용자는 후보 중 선택하거나 직접 다른 대상자를 제안할 수 있다.
- 확정된 대상자를 이후 5~7단계의 난이도 기준으로 계속 참조한다.

### 5. 과정목표 확정 (1개)
- 확정된 대상자 수준에 맞춘 과정목표 후보 3개를 제시한다.
- 사용자가 선택하거나 직접 입력한 목표로 1개를 확정한다. (과정목표는 항상 1개 — 여러 개를 원하면 세부 학습목표로 유도한다.)

### 6. 세부 학습목표 확정 (N개)
- 각 세부 학습목표 항목마다 후보 3개를 제시한다(전체를 한 번에 3개만 주는 것이 아니라, 목표 항목 단위로 반복 제시).
- 사용자가 몇 개까지 정할지 정할 때까지 반복한다. 완전 초보 대상자라면 항목 수를 과하게 늘리지 않도록 안내한다(대상자 난이도와 항목 수가 어긋나지 않게).

### 7. 차시표 작성
- 차시 수, 차시명, 차시내용을 표로 함께 정리한다. 컬럼: 번호(chNN) / 차시명 / 차시내용(원고를 바로 쓸 수 있을 정도로 구체적으로) / 실습 여부(있음/없음).
- 실습이 있는 차시들은 **하나의 실습 도메인**으로 이어가도록 제안한다(예: 1차시부터 마지막 차시까지 "Todo" 도메인 하나를 확장하며 실습). 사용자가 다른 도메인을 원하면 그에 맞춘다.
- NCS 연계가 있는 과정(국비/기관 과정 등)이면 능력단위요소를 차시별로 매핑한다. 해당 없으면 개요서에 "해당 없음"이라고 명시한다.

### 8. 개요서 확정
- 지금까지 확정된 내용(과정명/대상자/과정목표/세부목표/차시표/NCS 연계/실습 도메인 연속성)으로 개요서 초안을 만들어 사용자에게 보여준다.
- 사용자 확인·수정을 거쳐 확정되면 `courses/{id}/1.과정개요서.md`로 저장한다.
- `templates/status_template.md`를 읽어 `courses/{id}/status.md`를 새로 만든다. 차시 행 수는 확정된 차시 수와 같게 만들고(ch01, ch02, … 순서로 필요한 만큼 행 추가), 상단의 "과정개요서: ⬜"를 "과정개요서: ✅"로 바꾼다.
- status.md의 "다음 할 일"은 "ch01 원고초안 작성(manuscript-draft)"처럼 다음 단계를 가리키도록 갱신한다.

## 확정 체크리스트
개요서를 확정 저장하기 전에 아래를 모두 확인한다. 하나라도 실패하면 **repair 규칙**에 따라 해당 단계로 돌아간다.
- [ ] 필수 섹션 7종(과정명/대상자/과정목표/세부 학습목표/차시표/NCS 연계/실습 도메인 연속성)이 모두 존재한다(해당 없음도 명시적 기재로 인정).
- [ ] 차시표의 각 차시 행에 차시내용과 실습 여부가 빠짐없이 기재되어 있다.
- [ ] 대상자·과정목표·차시 난이도가 서로 어긋나지 않는다(예: 완전 초보 대상자인데 차시내용이 실무 심화 수준으로 튀지 않는지).

## repair 규칙
확정 체크리스트에서 실패한 항목이 있으면 **전체를 재시작하지 않는다.** 실패 항목이 유래한 대화 단계로만 돌아가 다시 확인/재확정한다.
- 필수 섹션 누락 → 해당 섹션을 다루는 단계(4단계: 대상자, 5단계: 과정목표, 6단계: 세부목표, 7단계: 차시표/NCS/실습 도메인)로 돌아가 그 섹션만 다시 채운다.
- 차시표 내용·실습 여부 누락 → 7단계로 돌아가 누락된 차시 행만 보완한다.
- 대상자·목표·난이도 불일치 → 먼저 4단계(대상자)가 맞는지 사용자에게 재확인한다. 대상자가 맞다면 5~7단계 중 어긋난 항목만 그 대상자 기준으로 다시 후보를 제시해 조정한다.
- 재확정이 끝나면 확정 체크리스트를 처음부터 다시 통과하는지 확인한 뒤에만 저장을 진행한다.
