# 원고 스키마 (`manuscript-draft` / `manuscript-final` 공용 규범)

이 문서는 스펙 §6을 규범화한 것이다. **기준(golden)은 `templates/golden/manuscript_golden.md`** (= `courses/spring-boot-basic/manuscripts/ch01.md`와 동일 내용) 이며, 이 문서와 골든이 어긋나면 골든이 맞다. 표기(필드명 볼드체, 대소문자, 콜론 유무, 구분선 위치)는 전부 골든의 실제 표기를 그대로 옮긴 것이다.

## 1. 파일 전체 구조

```
# {N}차시 원고: {회차명}

## 차시 정보

- 과정명: ...
- 회차명: ...
- 차시 목표: ...
- NCS 연계: ... (해당 없으면 "해당 없음"으로 명기 — 필드 생략 금지)
- 예상 분량: ...

## 사용 출처

- {출처명}: {URL}
- ...

---

## Slide 1. {슬라이드 제목}

**Screen**
...
**Easy analogy**
...
**Practical case**
...
**Visual asset**
...
**Source**
...
**Narration**
...
**Practice**
...
**Assessment**
...

---

## Slide 2. {슬라이드 제목}
... (반복)

---

## Slide N. 참고자료      <!-- 마지막 슬라이드 권장(필수 아님): 사용 출처 목록을 URL과 함께 재정리 -->
```

- 차시 헤더(제목 + `## 차시 정보` + `## 사용 출처`) 다음에 `---` 로 슬라이드 구간을 연다.
- 슬라이드 블록마다 앞뒤로 `---` 구분선을 둔다(골든 전체가 이 패턴).
- 슬라이드 블록은 **헤더 1줄(`## Slide N. 제목`) + 필드 8개(순서 고정)** 로 구성된다. 브리프의 "9필드" 표현은 이 헤더 1줄 + 필드 8개를 합쳐 부르는 표현이며, 실제 라벨은 아래 8개뿐이다(Step 3 검증도 이 8개 라벨만 grep한다).

## 2. 차시 헤더 필드 (순서 고정)

1. **과정명** — 과정개요서의 과정명 그대로.
2. **회차명** — 과정개요서 차시표의 해당 차시명.
3. **차시 목표** — 과정개요서 해당 차시 내용을 문장으로 풀어 쓴 목표. 여러 개면 한 문장에 이어 쓴다(골든 예시 참고).
4. **NCS 연계** — 과정개요서에 NCS 능력단위요소가 있으면 코드까지 인용(예: `` `2001020211_23v6-1.1` ``). 해당 없으면 **"해당 없음"**으로 명기한다(필드 자체를 생략하지 않는다).
5. **예상 분량** — 골든 표현 준수: "30분 이상 초안. 사용자가 추후 축약 가능하도록 풍부하게 구성한다." (§4 초안 원칙과 동일한 취지를 여기서도 명시).

`## 사용 출처` 섹션은 이 차시에서 실제로 인용한 모든 출처를 불릿으로 나열한다(리서치 md에서 가져온 것 + 새로 웹서치한 것 포함). 각 항목은 `- {출처명}: {URL}` 형식.

## 3. 슬라이드 블록 — 8개 필드 (순서 고정, 라벨 표기 그대로)

라벨은 반드시 `**Screen**`처럼 볼드 처리하고, 이 순서를 지킨다. 해당 없음은 필드를 지우지 말고 `- 없음.` 로 명기한다(뒤에 짧은 사유를 덧붙여도 된다. 예: `- 없음. 과정 도입.`).

1. **Screen** — PPT 화면 구성: 제목, 짧은 문구(불릿), 화면 배치 설명. 평가 슬라이드는 여기에 "문제:"와 보기(4지선다는 1~4번, 진위형은 O/X 형태의 진술문)를 적는다.
2. **Easy analogy** — 초보자용 쉬운 비유 1개(일상 사물/상황 비유).
3. **Practical case** — 실무 사례 또는 교육용 시나리오("교육용 시나리오: ..." 또는 "실무사례형 시나리오: ..."로 시작하는 관례를 따른다).
4. **Visual asset** — 아래 §4의 하위 유형 중 하나 이상.
5. **Source** — 이 슬라이드 내용의 근거. **"없음"을 쓰지 않는다** — 골든의 모든 슬라이드(평가·정리 슬라이드 포함)가 실제 출처명 또는 과정개요서 문서명을 인용한다. 리서치 md의 주장-출처 쌍에서 가져오거나, 새 주장이면 웹서치로 출처를 확보한 뒤 인용한다.
6. **Narration** — 강사가 그대로 소리 내어 읽을 수 있는 완결된 한국어 존댓말 문장(합니다체). 불릿이 아니라 문단으로 쓴다. 압축하지 않는다(§6 참고).
7. **Practice** — 실습 단계(IDE 조작·코드 작성·실행·확인 등)를 불릿으로. 실습이 없는 슬라이드는 `- 없음.`
8. **Assessment** — 일반 슬라이드는 `- 없음.` 평가 슬라이드는 §5 형식을 따른다.

## 4. Visual asset 하위 유형

슬라이드 성격에 맞춰 아래 중 하나 이상을 조합한다(골든에 실제 등장한 유형만 표준으로 삼는다):

- **GPT image prompt:** — 백틱(`` ` ``)으로 감싼 영문 프롬프트 한 줄. 예: `` GPT image prompt: `A clean educational illustration ...` ``. 만화식 2컷은 `Comic panel prompt:` 라벨을 대신 쓴다.
- **D2 초안** — 참조 파일 경로를 먼저 한 줄 적고(`` D2 diagram: `assets/diagrams/chNN_slug.d2` ``), 바로 아래에 ` ```d2 ` 코드펜스로 실제 D2 소스를 포함한다. 이미 만든 다이어그램을 재사용할 때는 `Reuse D2: {파일명}` 한 줄로 대체 가능.
- **화면 캡처 계획** — `Screenshot plan:` 라벨 뒤 번호 매긴 목록으로 캡처할 화면 순서를 적는다(실습/실행 결과 확인 슬라이드에 사용).
- **코드 블록** — `Code block for slide:` 또는 `Code block for PPT:` 라벨 뒤 ` ```{language} ` 코드펜스(java/http 등). 여러 언어 블록을 연달아 넣을 수 있다.

한 슬라이드에 두 유형을 함께 쓸 수 있다(예: GPT image prompt + Code block, Screenshot plan + GPT support image prompt).

## 5. 평가 규칙 (차시당 4지선다 1 + 진위형 2)

차시 끝부분에 평가 전용 슬라이드를 3개 둔다: `## Slide N. 평가하기 1: 사지선다형`, `## Slide N+1. 평가하기 2: 진위형`, `## Slide N+2. 평가하기 3: 진위형`.

- **Screen**: "제목: 평가하기" + "문제: {문제 본문}". 4지선다형은 보기 1~4번을 번호 목록으로 적는다. 진위형은 O/X로 판정할 진술문 하나를 적는다.
- **Easy analogy / Practical case / Visual asset**: 문항 이해를 돕는 보조 자료(다른 슬라이드와 동일 규칙, 생략 시 `- 없음.`은 지양 — 골든은 평가 슬라이드에도 실제 비유·사례를 채운다).
- **Source**: 해당 문항 근거 출처.
- **Narration**: 정답과 해설을 말로 풀어 설명하는 존댓말 문단(정답 번호/O·X를 명시적으로 언급).
- **Practice**: `- 없음.`
- **Assessment** (구조화된 하위 필드, 순서 고정):
  - `유형:` 사지선다형 | 진위형
  - `정답:` (사지선다형은 번호, 진위형은 O 또는 X)
  - `난이도:` 쉬움 | 보통 | 어려움
  - `해설:` 한 문장 요약 해설
  - `관련학습보기:` 근거가 된 본문 슬라이드 번호(들), 예: `Slide 10, Slide 11, Slide 15`

## 6. 초안 원칙

- **압축 금지** — 슬라이드 수·나레이션 분량을 줄이지 않는다. 차시당 30분 초과를 허용한다.
- 덜어내기·요약은 `manuscript-final` 단계에서 사용자와의 티키타카로 수행한다. `manuscript-draft`는 풍부하게 채우는 단계다.
- 8개 필드 중 해당 없는 필드도 **생략하지 않고** `- 없음.`으로 명기한다(Source 제외 — §3-5 참고).

## 7. 골든 예시

전체 예시는 `templates/golden/manuscript_golden.md` (26개 슬라이드 완주본, 표지→도입→본문→실습 6단계→정리→평가 3문항→참고자료 구성)를 참고한다. 새 차시를 쓸 때 이 파일을 열어 각 필드의 문체·분량 감각을 그대로 따라간다.
