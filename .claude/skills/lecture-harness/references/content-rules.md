# 공통 콘텐츠 규칙

세 제작 라인이 공유하는 내용 품질 규칙.

## (a) 출처 인용 정책

Manifest `constraints.citation_required_for`에 해당하는 주장은 원고/슬라이드에 출처를 표기한다.

| 대상 | 예 | 표기 |
|------|-----|------|
| statistics | "쿼리가 40% 감소" | 측정 조건 + 출처 |
| news | "2025년 X사 장애" | 매체/발표 + 날짜 |
| version_specific_claims | "Spring Boot 3.x부터 기본값" | 공식 문서/릴리스 노트 |
| external_case_studies | "Y사는 이렇게 해결" | 발표 자료/블로그 원문 |

- 출처를 확인할 수 없으면: 주장을 빼거나 "확인 필요"로 표시하고 게이트 보고에 명시한다. 그럴듯한 통념을 사실처럼 쓰지 않는다.
- research brief는 주장-출처 쌍으로 기록한다. brief에 없는 통계·사례를 원고 단계에서 만들어 넣지 않는다.
- 인용구는 실제 출처가 있는 것만 (저자·작품·연도).

## (b) 이론형 레슨 서사 구조

THEORY 레슨 원고는 정의 나열이 아니라 다음 흐름을 따른다.

```text
문제 상황 → 기존 방식 → 기존 방식이 깨지는 지점 → 기술이 나온 배경
→ 핵심 구조 → 실제 동작 흐름 → 대체 기술과의 차이 → 현업 사례
→ 언제 사용하고 언제 피할지
```

- 주제에 따라 중간 단계는 생략 가능하지만, **"문제 상황으로 시작"과 "언제 쓰고 언제 피할지로 마무리"는 고정**이다. 이유: 학습자가 기술을 도구로 판단하는 능력이 목표이지, 정의 암기가 목표가 아니다.
- 예 (N+1): 잘 동작하는 서비스 → 사용자 증가로 쿼리 급증 → 로그로 발견 → ORM이 왜 이런 쿼리를 내는가 → Fetch Join/EntityGraph/Batch Fetch 비교 → 무조건 Fetch Join이 답이 아닌 이유 → 코드 개선.
- 비유는 중심 비유 1개를 끝까지 유지하되, 비유가 사실을 왜곡하는 지점에서는 비유를 버리고 직설한다.

## (e) 원고 자수 예산 선반영 (v1.5)

script 계열 에이전트는 원고 착수 시 **`duration_minutes × 250~300자(공백 제외)`를 목표 자수로 먼저 정하고** 그 예산 안에서 서사를 설계한다. 예산을 넘는 서사는 쓰고 나서 줄이는 게 아니라 설계 단계에서 범위를 좁힌다 (다음 편/레슨으로 유예하고 그 사실을 반환에 명시).

근거: 자수 예산 없이 쓴 원고는 일관되게 27~39% 초과했고(드라이런 실측), 한국어 자연 발화 상한(~330자/분) 때문에 프롬프터 단계의 압축으로는 회복이 불가능하다. 길이 판정의 권위는 여전히 프롬프터 검증이다 — 이 규칙은 그 검증을 통과할 원고를 처음부터 쓰게 하는 사전 장치다.

## (f) 원고 = 책 — 시드 데이터 + 렌더된 시각 자료 (v1.8 개정)

**원고는 발화 대본이자 "읽는 책"이다** (사용자 정의): 열었을 때 도형이 그림으로 보이고, 이미지가 삽입되어 있고, 쉬운 예시/비유가 본문에 풍부해야 한다. 동시에 슬라이드·시뮬레이터의 원천(시드 데이터)이기도 하다.

### 표기 계약 (v1.8 — 구 `[IMG: ...]` 폐기)

| 요소 | 형식 | 처리 |
|------|------|------|
| **이미지** | image-gen 스킬 계약: `<!-- [IMAGE PROMPT: id]` + 프롬프트 서술 + `path: courses/{id}/images/{파일}.png` + `-->` + `![alt](../images/{파일}.png)` (+선택 `*캡션*`) | 북 빌드 단계에서 `image_gen.py`가 codex spawn으로 생성 → path에 저장 → `<img>` 치환. **path는 repo 루트 상대(저장 위치), 이미지 라인은 원고 파일 기준 상대(`../images/`)** — 혼동 금지 |
| **도형** | ` ```d2 ... ``` ` 코드블록(시드 원본 — 유지) **+ 바로 아래** `![도형 설명](../images/{파일}.svg)` 렌더 병기. **스타일: pub-d2-diagram 디자인 규칙 준수** — 3색 모노톤(`#f0f0f0` 입력/시작, `white` 처리/결과, `#eeeeee` DB), 점선=문제/불확실, `direction: right`, classes 시스템 권장 | 북 빌드 단계에서 `python .claude/skills/pub-d2-diagram/scripts/render_md_diagrams.py` (ELK + 모노톤 SVG) |
| **비유** | `[비유: 개념 ↔ 일상 소재 — 성립 조건 한 줄]` 블록 + **본문 서사에 풀어쓴 예시/비유 문단(발화)** | 블록은 시드, 본문 문단은 정상 발화 |

### 밀도 규칙 (v1.8 강화)

- **주요 섹션(H2/H3 중 학습 전환 단위)마다**: 쉬운 예시 또는 비유 서술(본문 발화) 1개 이상 **+** 시각 요소(렌더된 d2 SVG 또는 생성 이미지) 1개 이상. 시뮬 STEP 마커마다 강제하지 않는다 (과잉 방지).
- 중심 비유 1개 유지 원칙(위 (b))은 그대로 — 보조 비유는 국면별 적용이며, 사실을 왜곡하는 지점에서는 비유를 버린다고 명시.

### 북 빌드 단계 (파이프라인 위치: script 뒤, prompter **앞** — v1.8 신설, v1.9 도형 파이프라인 교체)

오케스트레이터가 수행: ① `python .claude/skills/image-gen/scripts/image_gen.py <원고.md> <repo루트>` ② d2 블록 → `render_md_diagrams.py`로 ELK+모노톤 SVG 렌더 (pub-d2-diagram 파이프라인). 프롬프터가 최종 원고(이미지·SVG 포함)를 받아야 비발화 제외가 정확해진다.

### 소비·검증 계약

- 스토리보드는 원고의 시드(d2 블록, **[IMAGE PROMPT] 블록/생성 이미지**, [비유])를 우선 소비. 시드에 없는 도형 창작 시 보고 (원고 개정 신호). **모든 시드가 슬라이드로 가야 하는 것은 아니다** — 원고 전용(책 독자용) 시각 요소도 정당하며, 스토리보드는 필요한 도형만 시드에서 가져온다 (v1.8).
- **비발화(프롬프터 자수 제외)**: `<!-- [IMAGE PROMPT...] -->` 주석, `![...](...)` 라인, 치환 후 `<img ...>`, SVG 병기 라인, `*캡션*`, d2 코드블록, [비유] 블록.
- QA 검사: `[IMG:` 잔존 0 / [IMAGE PROMPT] 블록마다 path 존재 / path 파일 실존 / 원고 이미지 링크 유효 / d2 블록 수 == 렌더 SVG 수 / 프롬프터 자수 제외 준수 / 스토리보드 시드 소비.

## (c) 시뮬레이터 프로파일

같은 edu-sim-builder를 쓰되 라인별 요구를 프로파일로 주입한다. 요구가 실제로 갈라지면 그때 스킬을 분리한다 (선제 분리 금지).

| 프로파일 | 라인 | 요구사항 |
|----------|------|----------|
| `filmed` | 촬영 | 강사가 나레이션 타이밍에 맞춰 조작. step 진행이 예측 가능해야 함 (자동 재생·랜덤 요소 지양) |
| `offline_interactive` | 오프라인 | 강사가 수업 중 실시간 조작. 즉석 질문 대응용 자유 탐색(파라미터 조절) 허용 |
| `online_self_paced` | 온라인 | 학습자 혼자 조작. 시작 안내 문구, 리셋 버튼, 단계별 진행 표시 필수 |

공통 불변: 단일 HTML 별도 파일, 슬라이드 내장 금지, 원고/슬라이드에는 실행 cue만.

## (d) 판서 엔진 슬라이드 2프로파일 규칙 (v1.7 개정)

모든 슬라이드는 panseo-slide 스킬(판서 엔진 소유)의 두 프로파일 중 하나다. **Registry 타입이 최종 의미** — 프로파일 정의 전문은 `.claude/skills/panseo-slide/SKILL.md` "하네스 통합 재정의".

| | `rich` (풍부) | `summary` (요약/판서용) |
|---|---|---|
| 밀도 | 고밀도 허용 (≤45단어, 도형·코드칩) — 빈 덱이면 실패 | 글자 적게, 컷당 한 줄, 판서 여백 — 고밀도면 실패 (인수인계 확정 조항) |
| Registry | `html_slide` (판서대본 없음) | `panseo_slide_html` + `panseo_script` (항상 2개) |
| 라인 | 촬영 **고정** / 오프라인 선택 | 온라인(유튜브 판서 VOD) **고정** / 오프라인 선택 |
| 판서 | 유사시 (예외 상황용) | **수업 설계의 전제** (강사가 무조건 판서) |

- 오프라인 선택은 G1 manifest `style.slide_mode`, G5에서 레슨 예외 가능.
- 완성 구조도는 rich의 도형 원천 가능, **summary에는 직접 파생 금지** (선택 참고만).
- 빈 판서보드(panseo-board): 명시 요청 시에만. 기본 파이프라인 연결 금지.
