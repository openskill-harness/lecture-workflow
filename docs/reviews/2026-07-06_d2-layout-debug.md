# systematic-debugging: D2 다이어그램 라벨 겹침·글자 넘침·여백 문제

- 날짜: 2026-07-06
- 방법: superpowers:systematic-debugging (근본 원인 → 수정)
- 대상: pub-d2-diagram 렌더 파이프라인

## 증상 (사용자 보고)
1. 도형에 여백이 부족하다.
2. 글자가 도형을 빠져나온다.
3. 도형을 연결하는 선 위에 글자(엣지 라벨)가 겹친다.

## Phase 1~3: 근본 원인 조사

**증거 수집(렌더된 PNG 육안):**
- slide08: 양방향 WAS↔DB 엣지 라벨("데이터 조회/저장", "결과")이 서로 겹치며 연결선 위에 얹혀 있음.
- slide10: 엣지 라벨 "서버 준비 완료"가 인접 노드("localhost:8080") 도형을 덮음.

**파이프라인:** `render_md_diagrams.py` → `d2.exe --layout elk --pad 40` → sed 모노톤 → playwright PNG.

**대조 실험(같은 D2 소스, elk vs dagre):**
- **elk**: 엣지 라벨을 연결선 중앙에 공간 예약 없이 배치 → 짧은 엣지·인접 노드에서 라벨이 선/노드와 겹침.
- **dagre**: 엣지 라벨을 공간 예약 요소(가상 노드)로 취급 → 라벨이 선 옆/위에 간격을 두고 배치, 겹침 없음. slide08의 양방향 라벨도 위/아래로 깨끗이 분리(elk에서 SVG 좌표를 수동 보정해야 했던 케이스).

**근본 원인 확정:**
> `--layout elk`가 엣지 라벨을 연결선/노드 위에 공간 예약 없이 배치하는 것이 세 증상의 공통 근본 원인. dagre는 엣지 라벨 공간을 예약해 설계상 겹치지 않고, 그 과정에서 노드 텍스트 여백도 확보된다.

부차 원인: 렌더 가드가 `direction: right`를 **강제**해(누락 시 실패) 선형 체인이 극단적으로 넓어지고(9:1~19:1), 이를 elk+grid/vertical로 우회하다 라벨 겹침이 악화됨.

## Phase 4: 수정 (하네스)

`render_md_diagrams.py`:
- `--layout elk` → `--layout dagre`.
- 가드: `direction: right` 강제 → `right` 또는 `down` 허용(명시는 요구). 선형 체인은 `down`이 종횡비에 유리.

`pub-d2-diagram/SKILL.md`: 레이아웃 dagre로 개정(elk 금지 사유 명기), direction right|down 가이드, 종횡비 3:1 가이드 유지.

## 검증 (수정된 파이프라인으로 ch01 5개 D2 재렌더)
| 파일 | 이전(elk) | 이후(dagre) | 라벨 겹침 |
|---|---|---|---|
| slide05-http | 2.46:1(grid hack) | 0.34:1(down) | 없음 ✅ |
| slide08-was | 0.85:1(수동 좌표 보정) | 1.09:1 | 없음 ✅(수동 보정 불필요) |
| slide10-embedded | 1.45:1(grid-rows 3) | 0.45:1(down) | 없음 ✅ |
| slide15-webmvc | 0.64:1 | 0.79:1 | 없음 ✅ |
| slide20-flow | 2.52:1 | 0.41:1(down) | 없음 ✅ |

전부 종횡비 ≤3:1, 엣지 라벨 겹침 0, 글자가 도형 내부에 여백과 함께 배치됨. elk 시절의 SVG 좌표 수동 보정·grid 해킹이 모두 불필요해짐.

선형 체인이 세로형(0.3~0.5:1)으로 나오나, 소비 산출물의 `object-fit: contain`으로 캔버스에 맞게 임베드되고 책(세로 페이지)에는 오히려 적합. 더 정사각에 가깝게 하려면 2열 그리드 재배치(수동)가 가능하나 필수는 아님.
