# L01 슬라이드 스토리보드 — Spring MVC는 요청을 왜 DispatcherServlet에 몰아주는가

## 설계 개요

- **총 9장.** 프롬프터의 잠정 SLIDE 01~09 마커와 1:1 대응 (재분할·병합 없음).
- **1장 = 1메시지** 원칙 준수. 원고 8개 섹션 중 섹션 5(핵심 구조)만 두 장으로 분리 —
  05는 "DispatcherServlet = 중앙 서블릿 정의"(개념), 06은 "안내데스크 비유"(직관)로 메시지가 다르므로 분할이 정당. 이는 프롬프터 baseline과 동일하여 조정 아님.
- **비유 등장 지점:** 중심 비유(안내데스크)는 원고상 섹션 5에서만 나오므로 SLIDE 06 한 장에만 시각화한다. 앞 슬라이드에 비유를 미리 심지 않는다(원고에 없음).
- **코드 슬라이드 없음 / SIM cue 없음.** `@GetMapping`은 실행 코드가 아니라 "스프링이 어떻게 아는가"를 던지는 개념 칩으로만 등장. code_font_min_pt(22pt)는 이 개념 칩에도 동일 적용.
- **단어 수 규칙:** 본문(제목+글머리+다이어그램 라벨) 어절 기준으로 카운트. 하단 각주(출처 표기)는 저작권·신뢰성 표기이므로 본문 단어 수에서 제외하되, 각주도 1행으로 짧게 유지.
- **비주얼 연속성:** SLIDE 04(Front Controller 박스) → 05(같은 박스에 DispatcherServlet 라벨 오버레이) → 06(같은 구조를 안내데스크 그림으로) → 08(같은 중앙 박스에 위임 슬롯 교체)로, 하나의 중앙 박스가 형태를 유지하며 진화하도록 조립 지시.

## SLIDE 01 — 문제 제기 (시작 고정)

- **프롬프터 대응:** `[SLIDE 01]`
- **핵심 메시지(한 줄):** `@GetMapping` 하나로 URL이 메서드에 연결되는데 — 스프링은 이 매핑을 대체 어떻게 아는가?
- **구성 요소 명세:**
  - 제목: `스프링은 이 매핑을 어떻게 알까?`
  - 개념 칩(코드 폰트 ≥22pt): `@GetMapping("/hello")` → `hello()` 메서드
  - 다이어그램: 칩과 메서드를 잇는 화살표 위에 **큰 물음표(?)** 하나. 화살표 = "연결은 되는데 원리는 미궁"을 시각화.
  - 하단 힌트 라벨: `→ 서블릿 시대로 돌아가 봅시다`
  - 강조: 물음표를 accent 컬러로. 나머지는 차분하게(질문을 남기고 다음 장으로).
- **단어 수 추정:** 본문 약 9어절 (제목 4 + 힌트 3 + 칩 라벨 2). **PASS (≤45)**
- **각주:** 없음 (일반 상식·질문 슬라이드, 인용 없음)

## SLIDE 02 — 기존 방식: 서블릿 직접 매핑

- **프롬프터 대응:** `[SLIDE 02]`
- **핵심 메시지(한 줄):** 옛날엔 URL 하나에 서블릿 하나를 직접 매핑하고, 각 서블릿이 자기 요청을 끝까지 처리했다.
- **구성 요소 명세:**
  - 제목: `예전엔 — URL 하나에 서블릿 하나`
  - 다이어그램: 3행 1:1 매핑 (코드 칩 ≥22pt)
    - `/login` → `[LoginServlet]`
    - `/order` → `[OrderServlet]`
    - `⋯` → `[⋯Servlet]` (더 있음을 점선 박스로)
  - 각 서블릿 박스 하단 캡션: `각자 요청을 끝까지 처리`
  - 강조: 세 박스를 나란히, 서로 **독립된 섬**처럼 배치(다음 장의 "중복" 대비용 여백 확보).
- **단어 수 추정:** 본문 약 12어절 (제목 5 + URL/서블릿 라벨 6 + 캡션 3, 중복 캡션 1회 카운트). **PASS**
- **각주:** 없음 (역사적 사실 서술, 특정 출처 인용 아님)

## SLIDE 03 — 깨지는 지점: 공통 관심사의 중복

- **프롬프터 대응:** `[SLIDE 03]`
- **핵심 메시지(한 줄):** 인증·로깅·예외처리 같은 공통 동작이 서블릿마다 복사되어 중복된다.
- **구성 요소 명세:**
  - 제목: `똑같은 일이 곳곳에 복사된다`
  - 다이어그램: SLIDE 02의 세 서블릿 박스를 재사용하되, **각 박스 안에 동일한 배지 3개** `[인증] [로깅] [예외처리]`를 반복 표시.
  - 강조: 반복되는 배지들을 red/warning 컬러로, 박스 간을 잇는 **중복(≒) 표시** 또는 겹쳐진 복사 아이콘. "서블릿 10개면 인증 코드 10벌"이라는 원고 문장을 `×10` 뱃지로 압축.
  - 보조 라벨: `흩어지면 → 바꾸기도 어렵다`
- **단어 수 추정:** 본문 약 11어절 (제목 4 + 배지 3 + 보조 3 + ×10 라벨 1). **PASS**
- **각주:** `Martin Fowler, PoEAA — Front Controller ("입력 컨트롤러 동작이 여러 객체에 흩어지면 상당 부분이 중복된다")` — 근거 인용, citation_required(external_case_studies/version-neutral 저작 인용)로 표기.

## SLIDE 04 — 등장 배경: Front Controller 패턴

- **프롬프터 대응:** `[SLIDE 04]`
- **핵심 메시지(한 줄):** 모든 요청을 단일 핸들러 하나로 통과시켜 — 공통은 먼저 처리하고, 고유 동작은 하위로 분배(dispatch)한다.
- **구성 요소 명세:**
  - 제목: `Front Controller 패턴`
  - 다이어그램(핵심): 좌측 **여러 요청(화살표 3~4개)** → 중앙 **단일 핸들러 박스**(라벨: `공통 동작 처리`) → 우측 **하위 객체 3개로 분배(dispatch)** 화살표.
  - 강조: 중앙 박스 하나로 요청이 **수렴**했다가 다시 **발산**하는 형태(깔때기 모양). "단일" 을 강조 컬러.
  - 라벨: 우측 분배 화살표에 `dispatch`, 하위 박스에 `요청별 고유 처리`.
- **단어 수 추정:** 본문 약 10어절 (제목 3 + 중앙 라벨 2 + dispatch 1 + 하위 라벨 2 + 요청 라벨 2). **PASS**
- **각주:** `Martin Fowler, PoEAA — Front Controller (단일 핸들러로 통합 후 하위 객체로 dispatch)` — citation_required.

## SLIDE 05 — 핵심 구조 ①: DispatcherServlet = 중앙 서블릿

- **프롬프터 대응:** `[SLIDE 05]`
- **핵심 메시지(한 줄):** Spring MVC에서 그 단일 핸들러가 `DispatcherServlet` — 요청 처리의 공통 알고리즘을 제공하는 중앙 서블릿이다.
- **구성 요소 명세:**
  - 제목: `그 핸들러가 = DispatcherServlet`
  - 다이어그램: SLIDE 04의 중앙 박스를 **그대로 이어받아** 라벨을 `Front Controller` → `DispatcherServlet`로 교체(연속성). 박스 안 두 줄:
    - `공통 알고리즘 제공 (중앙 서블릿)`
    - `실제 작업 → 위임 컴포넌트`
  - 강조: `DispatcherServlet` 을 코드 폰트 ≥22pt, accent 컬러. "공통 알고리즘"과 "위임"을 대비되게(한쪽은 고정, 한쪽은 교체 가능 뉘앙스).
- **단어 수 추정:** 본문 약 10어절 (제목 3 + 박스 2줄 7). **PASS**
- **각주:** `Spring Framework Reference — DispatcherServlet ("요청 처리의 공통 알고리즘을 제공하는 중앙 서블릿", 실제 작업은 설정 가능한 위임 컴포넌트)` — citation_required(version_specific_claims).

## SLIDE 06 — 핵심 구조 ②: 안내데스크 비유 (중심 비유)

- **프롬프터 대응:** `[SLIDE 06]`
- **핵심 메시지(한 줄):** `DispatcherServlet`은 건물 정문의 안내데스크 — 공통 절차를 먼저 처리한 뒤 담당 부서(컨트롤러)로 안내하고, `@GetMapping`을 찾아내(discover) 요청을 넘긴다.
- **구성 요소 명세:**
  - 제목: `건물 정문의 안내데스크`
  - 다이어그램(중심 비유, 이 강의의 앵커 이미지):
    - 좌측: 여러 **방문객(요청) 아이콘** 여럿.
    - 중앙: **정문 하나 + 안내데스크** — 라벨 `DispatcherServlet`. 데스크 위 캡션 `공통 절차 먼저`.
    - 우측: **부서 3개** 박스 — 라벨 `컨트롤러`. 데스크→부서 화살표.
  - 콜아웃 말풍선: `@GetMapping을 발견(discover) → 담당 부서로 안내` (코드 칩 ≥22pt)
  - 강조: 정문이 **하나**임을 시각적으로(입구 아이콘 강조). 방문객이 많아도 입구는 하나.
  - 조립 지시: SLIDE 05의 중앙 박스 위치와 겹쳐 보이도록 배치해 "정의 → 비유"가 같은 대상임을 전달.
- **단어 수 추정:** 본문 약 13어절 (제목 3 + 방문객/요청 1 + 중앙 라벨+캡션 3 + 부서/컨트롤러 2 + 콜아웃 4). **PASS**
- **각주:** `Spring Framework Reference — DispatcherServlet (위임 컴포넌트를 스프링 설정에서 "discover")` — citation_required(version_specific_claims).

## SLIDE 07 — 대체 기술: 웹 프레임워크의 공통 설계

- **프롬프터 대응:** `[SLIDE 07]`
- **핵심 메시지(한 줄):** 중앙 진입점 하나를 두는 것은 스프링만의 발명이 아니라 웹 프레임워크 전반의 공통 설계다.
- **구성 요소 명세:**
  - 제목: `스프링만의 발명이 아니다`
  - 다이어그램: **일반 웹 프레임워크 박스 3개**(특정 프레임워크명 표기 금지 — 원고에 이름 없음). 각 박스마다 `단일 진입점` 아이콘(작은 정문/도트) 하나씩.
  - 강조: 세 박스에 **공통으로** 찍힌 단일-진입점 아이콘을 같은 accent 컬러로 묶어 "패턴의 보편성"을 표현.
  - 보조 라벨: `웹 프레임워크 전반의 공통 설계`
- **단어 수 추정:** 본문 약 8어절 (제목 3 + 진입점 라벨 2 + 보조 3). **PASS**

## SLIDE 08 — 언제·왜 유용한가 (마무리 고정)

- **프롬프터 대응:** `[SLIDE 08]`
- **핵심 메시지(한 줄):** 공통은 한곳에서 표준화하고 위임 컴포넌트만 바꾸면 다양한 워크플로를 유연하게 수용하며, 불필요한 단계는 강제되지 않는다.
- **구성 요소 명세:**
  - 제목: `공통은 표준화, 나머지는 갈아끼운다`
  - 다이어그램: SLIDE 05의 중앙 박스 재사용 — `DispatcherServlet`(고정) + 하단에 **교체 가능한 위임 슬롯 3칸**(플러그/카트리지 아이콘). 슬롯 중 하나는 회색 처리 + 라벨 `로케일 리졸버 — 불필요시 생략`.
  - 강조: 중앙 박스는 **고정(자물쇠 느낌)**, 슬롯은 **교체 가능(화살표 순환)** 대비. "유연 / 다양한 워크플로"를 accent.
  - 보조 라벨: `유연 · 다양한 워크플로 지원`
- **단어 수 추정:** 본문 약 12어절 (제목 5 + 슬롯 라벨 4 + 보조 3). **PASS**
- **각주:** `Spring Framework Reference — DispatcherServlet ("유연하며 다양한 워크플로를 지원") / Processing (불필요한 단계는 강제되지 않음)` — citation_required.

## SLIDE 09 — L02로 넘어가는 다리

- **프롬프터 대응:** `[SLIDE 09]`
- **핵심 메시지(한 줄):** 요청을 한곳에 몰아준 이유 = 공통은 모으고 개별은 나누기 위해서 — 다음엔 요청 한 건의 처리 순서를 직접 추적한다.
- **구성 요소 명세:**
  - 제목: `공통은 모으고, 개별은 나눈다`
  - 다이어그램: 한 줄 요약 카드(수렴→발산 미니 아이콘, SLIDE 04 깔때기 축소판) → 우측 **다음 시간 카드** `L02 — 요청 한 건을 순서대로 추적`.
  - 강조: "직접 눌러보며 추적"을 다음 편 예고 톤으로. **단, SIM cue 슬라이드 아님** — 실행/시뮬레이터 표기 없이 예고 텍스트만(원고: "SIM 예고 없음 — L02에서 실행").
  - 조립 지시: `[SIM]`·`[실행]` 같은 cue 마커를 넣지 말 것.
- **단어 수 추정:** 본문 약 9어절 (제목 4 + 다음 카드 라벨 5). **PASS**
- **각주:** 없음 (요약·예고 슬라이드)
