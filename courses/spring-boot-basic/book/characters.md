# 스프링 부트 기초 - 등장인물

`book-build` 스킬 `storytelling.md`의 캐릭터 삼각 구도를 스프링 부트 기초 과정(신입 백엔드 개발자 대상)에 맞춰 확정한 문서. 실명 대신 역할명만 쓴다.

## 배경 설정

무대는 사내 서비스를 만드는 개발팀. 오픈이는 이번 주 월요일에 입사한 신입 백엔드 개발자이며, 회사는 최근 사내 게시판과 API 서버를 스프링 부트 기반으로 새로 옮기는 중이다. 팀장과 동료는 이미 이 프로젝트에서 일한 지 각각 10년, 2년 된 사람들이다.

## 팀장 (힌트 제공자)

- **역할**: 소크라테스식 질문으로 방향만 던지고 답은 주지 않는다.
- **배경**: 백엔드 리드. 예전 방식(Tomcat 직접 설치, WAR 배포)부터 지금 방식까지 다 겪었다.
- **말투**: 캐주얼 존댓말(~해요, ~죠, ~해봐요). 짧은 한마디로 비유를 촉발시킨다. 정답을 바로 주지 않고 되묻는다.
- **예시 대사**: "그거, 식당이랑 비슷하지 않아요?" / "일단 켜 보고 다시 얘기해요."

## 동료 (문제 제기자)

- **역할**: 실사용 관점에서 날것의 불만과 새로운 문제를 던진다. 오픈이가 이미 겪은 시행착오를 자기 경험으로 되짚어 주기도 한다.
- **배경**: 입사 2년 차. 오픈이가 겪는 혼란을 얼마 전까지 자기도 겪었다.
- **말투**: 존댓말이지만 직설적이고 약간 투덜거리는 톤. 감탄사나 한숨 섞인 대사 허용.
- **예시 대사**: "저도 처음엔 그거 때문에 반나절 날렸어요." / "그거 API 문제 아니고 경로 오타예요, 십중팔구."

## 오픈이 (실행자, 독자 대리인)

- **역할**: 문제를 직접 겪고 실습을 손으로 진행한다. 독자가 감정을 이입하는 대상.
- **배경**: 컴퓨터공학 전공, 실무 경험은 없음. 이번 주 첫 출근.
- **말투**: 존댓말 유지(~이죠, ~합니다, ~이에요). 솔직한 궁금증과 당황을 그대로 드러낸다.
- **예시 대사**: "그럼 지금 제 컴퓨터 안에 서버가 떠 있는 거예요?" / "어, 방금까지 되던 게 왜 안 되죠?"

## 등장 규칙

- 2개 챕터(장) 연속으로 세 캐릭터가 모두 빠지는 구간을 만들지 않는다.
- 비유는 최소 1개 이상 캐릭터 대사에서 촉발시킨다(팀장의 힌트 한마디 → 오픈이가 비유를 떠올리는 패턴을 기본으로 삼는다).
- 동료는 챕터 도입부에서 문제를 던지고, 각 장의 실습이 끝나는 지점에서 검증자로 재등장해 결과를 확인해 준다(원형 서사).
