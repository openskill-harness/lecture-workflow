## P1 — SIMULATION 독립 레슨 폐지

- codex: 이번 인스턴스(L01+L02 통합)는 타당. **단 enum 완전 제거는 반대(blocker)** — 시뮬이 주인공인 explorable 콘텐츠·온라인 자기주도 강의 대비, "enum 유지 + filmed 원칙 금지"를 권고
- **처리: 기각 (사용자 결정 — 전 라인 완전 폐지).** 시뮬레이터는 슬라이드 설명의 보조 수단이라는 사용자의 제작 철학 우선. 추후 시뮬 중심 콘텐츠가 필요해지면 재설계. 채택된 세부: required_artifacts 부착 방식, 원고 시뮬 파트([SIM 실행]~[SIM 종료] + 파트 시간), "시뮬 전용 레슨 = 설계 오류" 분류 규칙

## P2 — concept_model + architecture_diagram

- codex: 방향 좋음. 위치는 G1 직후 생성 + **G2에서 레슨 플랜과 함께 승인**(별도 게이트 불필요), research-agent 확장 적정(출력 계약 명시 조건). **blocker: "상위 원천"을 판서슬라이드까지 확장 금지** — 인수인계 확정 조항과 충돌
- **처리: 전부 채택.** 소비 계약을 "시뮬 필수 기반 + rich 슬라이드·원고 d2 시드 참고 원천, 판서슬라이드(summary) 직접 파생 금지(선택 참고만)"로 제한

## P4 — 슬라이드 2프로파일 (촬영 rich 고정 / 오프라인 선택 / 온라인 summary 고정)

- codex: 방향 가능하나 명명 위험 — **"rich를 판서슬라이드의 모드로 부르면 '판서슬라이드는 글자가 적어야 한다' 확정 조항과 충돌(blocker)"**. panseo-slide를 "판서 엔진 소유 스킬"로 재선언하고 rich/summary를 "엔진 기반 슬라이드 프로파일"로, **Registry 타입이 최종 의미**(html_slide=고밀도 가능 / panseo_slide_html=반드시 저밀도)를 갖게 하라. 템플릿 이관은 장기적으로 타당(양쪽 회귀검증 조건). 오프라인 선택은 **G1 manifest**(G5는 늦음) + G5 레슨 예외. 산출물 계약: offline rich를 panseo_slide_html로 등록하면 QA 붕괴(blocker) → html_slide로
- **처리: 명명·계약·시점 전부 채택.** codex의 "온라인 2유형 분리(판서 VOD형/자기주도형)" 제안은 **기각 (사용자 정의 — 온라인 = 유튜브 판서 VOD 단일)**. 자기주도형이 필요해지면 확장. 시뮬레이터의 online_self_paced 장치는 시연+시청자 배포 겸용으로 유지
