# 제안: R1에 "결정 이유(why)는 현행 문서에 유지" 조항 추가

- 날짜: 2026-07-07
- 유형: 유지 규칙(R1) 문구 정교화 — `CLAUDE.md` + `harness-maintain` SKILL

## 문제
R1은 "폐기된 옛 설계를 인라인에 남기지 마라"까지만 규정한다. **"결정의 이유(why)는 남긴다"**가 명시돼 있지 않아, R1을 기계적으로 적용하면 정리하는 사람이 *옛 상태 서술*과 함께 *"왜 그렇게 결정했나"*까지 지워버릴 위험이 있다. (실제로 2026-07-05 spec 정리 시 이 구분이 필요했다 — 옛 구성은 history로, 결정 이유는 spec에 유지.)

## 제안
R1을 다음으로 정교화(완화 아님, 명확화):

- 현행: "권위 문서엔 현행 진실만 남긴다. 폐기된 개념·이전 설계·'예전엔 X였다'를 인라인에 남기지 않는다."
- 변경: "권위 문서엔 **현행 진실 + 그 결정의 이유(why)**만 남긴다. 폐기된 옛 상태·'예전엔 X였다'·1회성 이관 절차는 인라인에 남기지 않고 `docs/history/`로 보낸다. 단, **왜 지금 이렇게 결정했는가**(결정 이유)는 옛 상태 서술과 구분해 현행 문서에 유지한다."
- `harness-maintain` SKILL의 R1 요지 줄도 동일 취지로 갱신.

## 회귀 위험
- 규칙 완화가 아니라 명확화. 기존 R1 위반(옛 상태 인라인) 판정 기준은 그대로. "이유 보존"만 추가.
- audit grep(폐기/dead-link 등)에는 영향 없음 — 문구 추가일 뿐.

## 검증
- codex 사전검증(read-only).
- 반영 후: CLAUDE.md R1에 "이유(why)" 포함 확인, harness-maintain R1 줄 동기화 확인.
