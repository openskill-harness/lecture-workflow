# 코드 슬라이드 캔버스 오버플로 → PPTX 잘림 방지 규칙

- 날짜: 2026-07-08
- 대상: `.claude/skills/ppt-preview/SKILL.md`(주 소유자), 교차참조 `pptx-build`, `storyboard`
- 유형: 규칙 추가(R2 append) — 기존 규칙 교체 아님

## 문제

`ppt-preview`의 코드 슬라이드는 골든의 `code-canvas`/`.ppt-code-layout` + `pre code` 위젯을 쓴다. 골든 CSS의 `pre { overflow: auto; }` 때문에, 코드가 16:9 캔버스 높이를 넘기면 **캔버스 안에서 스크롤**된다.

`pptx-build` 기본 이미지 모드는 이 PPT프리뷰 HTML을 헤드리스 Chromium으로 **캔버스 프레임 그대로** 스크린샷해 PPTX 각 장의 전체 배경으로 넣는다(`render_preview_slides.py`가 `.ppt-slide .ppt-canvas`를 렌더). 스크롤 영역은 자동으로 펼쳐지지 않으므로, **화면에 보이는 윗부분만 찍히고 스크롤 아래쪽(코드 후반부)은 잘려나간다**. 화면(브라우저)에서는 스크롤로 다 보이므로 프리뷰 확정 시점에 놓치기 쉽다.

실사례: design-pattern ch01 Slide 8 — `Mem02.java`(주석·빈 줄 포함 약 44줄)가 좌측 설명 칼럼과 함께 우측 코드 칼럼에만 들어가 스크롤됐고, `main` 메서드(결론부)가 PPTX에서 잘릴 상태였다.

## 제안

`ppt-preview` SKILL.md §2 코드 슬라이드 지시에 규칙을 **추가**한다: 코드가 캔버스를 넘겨 스크롤될 상황이면 스크롤되는 `pre`를 그대로 두지 말고 아래 중 하나로 **스크롤 없이 전체를 한 화면에 노출**한다.

- (a) **2분할 코드 이미지** — 정의부/실행부 등 논리 경계로 코드를 나눠 각 조각을 이미지로 렌더해 캔버스에 나란히 배치. 이미지는 **검증된 소스**(`practice-code` 산출물 / 정답본)에서 렌더하고, 코드가 바뀌면 재생성한다. 저장 위치는 시각자산 이미지 폴더(`outputs/03_시각자산/images/chNN/slideNN-*.png`). 2단 배치 CSS는 스크롤 없는 flex(예: `.code-two-up`).
- (b) **슬라이드 분할** — 원고(SSOT) Slide N을 두 슬라이드로 나눔(manuscript-final 경유, 번호 재동기화 수반).
- (c) **fit-to-canvas 축소** — 좌측 설명 칼럼 제거·빈 줄 정리·폰트 축소로 스크롤 없이 한 캔버스에.

가독성 우선순위: 코드가 길면 (a) 또는 (b), 짧게 줄일 수 있으면 (c).

확정 체크리스트에 "코드 슬라이드 무스크롤" 항목을 추가한다.

### 교차참조

- `pptx-build` SKILL.md 이미지 모드 설명에 한 줄: 이미지 모드는 프리뷰 캔버스를 그대로 렌더하므로, 캔버스를 넘겨 스크롤되는 콘텐츠(특히 긴 코드)는 잘린다 — 무스크롤 보장은 `ppt-preview`가 소유(규칙 위치 포인터).
- `storyboard` SKILL.md 코드 위젯 언급에 한 줄: 코드가 프리뷰 셀을 넘기면 같은 2분할 이미지(있으면 재사용)로 대체 가능(강사 검수 카드라 스크롤이 치명적이진 않으나 일관).

## 회귀 위험

- 기존 "자산 임베드 안전 여백"(2026-07-06) 규칙과 무관(그건 이미지 여백, 이건 코드 오버플로) — 충돌 없음, append로 안전.
- 골든 `pre { overflow:auto }` 자체는 건드리지 않는다(짧은 코드는 그대로 유효). 규칙은 "넘칠 때만" 적용.
- (a) 방식의 코드 이미지는 manifest 관리 대상이 아닌 인라인 자산(코드블록이 원래 인라인이었던 것과 동일) — manifest 스키마 변경 불필요.
